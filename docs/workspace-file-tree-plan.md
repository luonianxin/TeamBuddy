# 对话工作台右侧工作区文件树实施方案

## 1. 文档状态

- 状态：已确认，待实施
- 目标版本：首期
- 目标页面：主要对话工作台 `/tasks`
- 核心约束：文件预览只读；支持任务绑定的全部工作目录；默认选中主 `work_dir`

## 2. 背景与目标

TeamBuddy 的任务已经绑定本地项目工作目录，用户在对话工作台中与 Agent 协作时，需要同时查看当前工作区的目录结构和文件内容，减少在 TeamBuddy 与外部编辑器之间切换的频率。

首期在 `/tasks` 页面右侧增加工作区文件面板，提供：

- 查看任务关联的全部工作目录。
- 默认选择主 `work_dir`，并可在右栏顶部切换其他 `work_dirs`。
- 按需展开目录树，查看文本、源码、Markdown、配置文件和常见图片。
- 文件内容严格只读，不提供保存、创建、删除、重命名或移动能力。
- 支持刷新、文件名搜索、面板折叠和宽度调整。
- 在窄窗口下切换为覆盖式 Drawer，避免压缩主要对话区域。

## 3. 可行性结论

可行性高，整体工作量中等。

当前代码已经具备以下基础：

- 任务模型包含 `work_dir`，并通过 `gt_task_work_dirs` 保存多个工作目录。
- `web/src/views/tasks/TaskNotifications.vue` 已采用可扩展的 Flex 分栏布局。
- `web/src/components/task-progress/TaskDocumentsDrawer.vue` 已实现文件树、文本/Markdown/图片展示、错误状态和可调宽度交互。
- `internal/localserver/tasks.go` 已具备任务文件读取、路径越界校验和符号链接防护逻辑。

现有能力不能直接复用为工作区浏览接口：

- 当前 `GET /tasks/:uuid/files` 读取的是 TeamBuddy 管理的 `task_dir`，不是项目源码所在的 `work_dir`。
- 当前目录接口会递归扫描整棵目录，大型仓库、`node_modules` 或构建目录可能造成明显阻塞。
- 当前内容读取没有适合源码仓库的文件大小限制。
- 当前文档抽屉允许编辑和保存，不符合首期只读要求。

因此应保留“任务产出文档”和“项目工作区文件”两套清晰边界，复用展示层能力，但不复用产出目录的写入语义。

## 4. 首期范围

### 4.1 包含

- 仅接入主要对话工作台 `/tasks`。
- 右侧可折叠、可调整宽度的工作区文件面板。
- 顶部工作目录切换器，默认选择主 `work_dir`。
- 多工作目录的独立展开状态和选中文件状态。
- 目录逐层懒加载。
- 文件名搜索和手动刷新。
- 文本、源码、Markdown、配置文件和常见图片的只读预览。
- 加载、空目录、目录不存在、无权限、文件被删除、二进制文件、文件过大等状态。
- Windows 与 macOS 路径兼容。
- 中英文国际化。

### 4.2 不包含

- 看板任务详情页 `TaskDetail.vue`。
- 文件编辑、保存、创建、删除、重命名、移动和拖放。
- 完整 IDE 能力，例如语法诊断、代码跳转、查找引用和终端集成。
- Git 文件状态装饰。
- 文件系统实时监听；首期使用手动刷新。
- 任意本地目录浏览；只能访问当前任务数据库记录中绑定的工作目录。

## 5. 交互设计

### 5.1 桌面布局

`TaskNotifications.vue` 的主区域扩展为三栏：

1. 左侧：现有会话列表。
2. 中间：现有对话内容和输入区。
3. 右侧：新增工作区文件面板。

建议初始参数：

- 默认宽度：300px。
- 最小宽度：240px。
- 最大宽度：480px，且不超过可用内容宽度的 45%。
- 支持拖动左侧分隔条调整宽度。
- 支持通过标题栏图标折叠或展开。
- 面板宽度和折叠状态保存在本地，不影响服务端任务数据。

当窗口不足以稳定展示三栏时，右栏切换为覆盖式 Drawer。断点应结合现有左侧栏宽度验证，初始建议约为 1000px，而不是直接沿用 700px 的移动端断点。

### 5.2 面板结构

右侧面板从上到下包含：

1. 标题与折叠按钮。
2. 工作目录选择器。
3. 搜索框、刷新按钮和更多菜单。
4. 文件树。
5. 文件预览区，或点击文件后打开只读预览 Drawer。

推荐首期采用“固定文件树 + 较宽只读预览 Drawer”：右栏保持适合浏览目录的宽度，代码、Markdown 和图片在更宽区域展示，避免在 300px 面板中形成不可用的预览体验。

### 5.3 工作目录切换

- roots 接口返回主目录和附加目录，并明确 `primary` 标记。
- 首次打开任务时默认选择 `primary=true` 的目录。
- 用户切换目录后，按任务 UUID 记忆选择结果。
- 每个工作目录分别记忆展开节点、选中文件和滚动位置。
- 如果记忆的目录已被任务移除，自动回退到主目录。
- 目录展示名优先使用项目名或目录末级名称，完整路径通过 Tooltip 展示。

### 5.4 文件树操作

- 点击目录：按需加载直属子项并展开或收起。
- 点击文件：加载只读预览。
- 刷新：刷新当前目录；不默认清空其他已加载分支。
- 搜索：按文件名搜索，设置最小输入长度、节流和结果上限。
- 键盘：支持焦点可见、方向键移动和展开、Enter 打开文件、Escape 关闭预览。
- 所有图标按钮必须提供 `title` 和 `aria-label`。

## 6. API 设计

API 继续放在本地任务路由下，所有接口均以任务 UUID 为授权边界。

### 6.1 获取工作目录

`GET /api/local/tasks/:uuid/workspace/roots`

响应示例：

```json
{
  "roots": [
    {
      "id": "root-0",
      "name": "TeamBuddy",
      "path": "D:\\workspace\\dsh\\TeamBuddy",
      "primary": true,
      "available": true
    }
  ]
}
```

要求：

- 根目录只能来自任务表和 `gt_task_work_dirs`。
- 去重时使用平台一致的规范化路径语义。
- `id` 应稳定且不可用于推导或替换成任意绝对路径。
- 不存在或无权限的目录仍可返回，但标记 `available=false` 并提供错误码。

### 6.2 枚举目录

`GET /api/local/tasks/:uuid/workspace/entries?root_id=root-0&path=src`

响应包含当前相对路径、直属子项、是否截断和上限信息。每个节点至少包含：

- `name`
- `path`：相对于选中 root 的路径
- `is_dir`
- `file_type`
- `size`
- `modified_at`
- `hidden`
- `ignored`

该接口每次只读取一层，不递归构造整棵树。

### 6.3 读取文件内容

`GET /api/local/tasks/:uuid/workspace/content?root_id=root-0&path=src/main.ts`

响应至少包含：

- 相对路径和文件名。
- 文件类型、MIME、大小和修改时间。
- `text`、`base64` 或 `unsupported` 编码标记。
- 内容，或文件过大/二进制不支持的错误码。

首期不增加任何工作区写入接口。

### 6.4 搜索文件

可在首期一并提供：

`GET /api/local/tasks/:uuid/workspace/search?root_id=root-0&q=config&limit=100`

搜索约束：

- 仅按文件和目录名称匹配，不搜索文件内容。
- 忽略默认排除目录。
- 限制最大遍历数量、结果数量和执行时间。
- 请求取消时立即停止遍历。

如果实施周期需要压缩，搜索可降级为仅过滤已经加载的节点，但 UI 必须明确其范围，不能让用户误以为已搜索整个工作区。

## 7. 安全设计

### 7.1 根目录授权

- 客户端不能提交任意绝对根路径。
- 服务端根据任务 UUID 查询允许访问的 roots。
- `root_id` 必须映射到该任务当前绑定的目录。
- roots 变化后，旧 `root_id` 不再可用。

### 7.2 路径校验

复用并泛化现有 `safeTaskFilePath` 语义：

- 拒绝绝对相对路径参数。
- 清理路径后拒绝 `..` 越界。
- 使用 `filepath.Rel` 验证目标仍在 root 内。
- 拒绝路径中包含符号链接的目标。
- 内容接口只允许读取普通文件。
- 目录接口只允许读取目录。

需要特别覆盖 Windows 盘符、大小写、UNC 路径和路径分隔符差异。

### 7.3 内容限制

建议默认限制：

- 文本文件：最大 2 MB。
- 图片文件：最大 10 MB。
- 单目录直属条目：最大 1000 个。
- 搜索结果：最大 100 条。

超限时返回结构化错误码和文件元数据，不读取完整内容。二进制文件不尝试转换为字符串。

### 7.4 敏感文件

工作区浏览本身可能暴露源码仓库内的密钥文件。首期建议：

- 默认允许显示普通点文件，以符合源码浏览预期。
- 对 `.env`、私钥、证书和常见凭证文件显示敏感提示。
- 不在日志中记录文件内容。
- API 错误日志只记录任务 UUID、root ID、相对路径和错误类型。
- 后续可增加管理员策略或敏感文件阻止列表；首期至少保证只读和本地 API Token 防护。

## 8. 性能策略

- 目录按层懒加载，禁止初始化时递归扫描整个仓库。
- 默认排除 `.git`、`node_modules`、`vendor`、`dist`、`build`、`.cache` 等高成本目录。
- 提供“显示已忽略项”选项，但 `.git` 内部数据建议始终不展开。
- 前端大型树使用 `shallowRef`，避免 Vue 对整棵嵌套树做深层响应式代理。
- 节点使用 root ID 与相对路径构造稳定 key，禁止使用数组下标。
- 切换任务、root 或搜索条件时取消旧请求，防止旧响应覆盖新状态。
- 已加载目录可以短期缓存；手动刷新后只失效对应分支。

## 9. 前端设计

### 9.1 建议新增模块

- `web/src/components/workspace/WorkspaceFilePanel.vue`
- `web/src/components/workspace/WorkspaceFileTree.vue`
- `web/src/components/workspace/WorkspaceFilePreview.vue`
- `web/src/composables/useWorkspaceFiles.ts`
- `web/src/types/workspace-files.ts`

### 9.2 接入点

在 `web/src/views/tasks/TaskNotifications.vue` 中：

- 在 `.task-layout` 内、`.conversation-main` 之后挂载文件面板。
- 只有存在已选择任务时才允许展开工作区面板。
- 传入 `selectedTaskUuid`，由工作区 composable 管理 roots 和节点请求。
- 切换任务时取消请求并恢复该任务的本地 UI 状态。
- 在页面标题栏操作区增加工作区面板切换按钮。

### 9.3 与现有文档抽屉的关系

`TaskDocumentsDrawer.vue` 继续负责 `task_dir` 产出文档，并保留编辑能力。

工作区预览使用独立组件，但可以提取和复用以下纯展示逻辑：

- 文件类型判断。
- 图片 Data URL 生成。
- 文件大小格式化。
- Markdown 预览。
- 加载、错误和不支持状态。

不得复用以下行为：

- 草稿缓存。
- 编辑器。
- 保存按钮。
- `POST /tasks/:uuid/files/content`。

## 10. 后端设计

建议在 `internal/localserver` 中新增独立文件，例如：

- `task_workspace_files.go`
- `task_workspace_files_test.go`

这样可以避免继续扩大已经较大的 `tasks.go`，并使安全边界、目录枚举和测试集中管理。

主要职责：

1. 加载并规范化任务工作目录列表。
2. 将 `root_id` 解析为已授权的本地根路径。
3. 安全解析相对路径。
4. 枚举单层目录并应用过滤、排序和数量限制。
5. 检测文本、图片、二进制和文件大小。
6. 返回稳定的结构化错误码。
7. 在请求 Context 取消时中止搜索或遍历。

## 11. 国际化与错误码

前端中英文资源至少增加：

- 工作区、主目录、切换目录。
- 搜索文件、刷新、折叠、展开。
- 显示或隐藏忽略项。
- 未绑定工作目录。
- 工作目录不存在或不可访问。
- 文件不存在、读取失败、文件已变化。
- 文件过大、二进制文件、不支持预览。
- 目录条目过多、结果已截断。
- 只读预览。

后端应返回稳定错误码，前端通过国际化资源生成用户文案，不依赖解析 Go 错误字符串。

## 12. 测试方案

### 12.1 Go 单元测试

至少覆盖：

- 主 `work_dir` 与多个附加 `work_dirs` 的顺序和去重。
- root ID 不能跨任务使用。
- 未授权 root ID 被拒绝。
- 绝对路径、`..`、混合分隔符路径越界被拒绝。
- 符号链接文件和目录被拒绝。
- 文件、目录类型校验。
- 文本、图片、二进制和无扩展名文件识别。
- 文本和图片大小上限。
- 单目录条目上限及截断标记。
- 目录优先、名称稳定排序。
- 不存在、无权限和读取期间被删除。
- Context 取消后搜索及时停止。

### 12.2 前端验证

当前仓库未配置前端组件测试框架，首期至少执行：

- `npm test`
- `npm run lint`
- `npm run build`

手工验证场景：

- 在两个及以上工作目录间切换，默认主目录正确。
- 快速切换任务和目录，没有旧响应串入当前任务。
- 展开、折叠、刷新和搜索行为正确。
- Markdown、源码、配置文件、图片、二进制和超大文件预览状态正确。
- Agent 修改文件后手动刷新可以看到变化。
- 1440px、1024px、700px 三档窗口没有内容重叠或不可访问操作。
- 所有操作可使用键盘完成，焦点状态可见。
- 包含数万文件和 `node_modules` 的仓库不会在打开面板时全量递归扫描。

后端完整验证：

## 13. 实施顺序

### 阶段一：后端只读能力

1. 定义 roots、entries、content 和 search 响应结构。
2. 实现工作目录加载和 root ID 映射。
3. 实现安全路径解析和单层目录枚举。
4. 实现文件内容识别与大小限制。
5. 添加 Go 单元测试。

### 阶段二：前端基础组件

1. 增加 TypeScript 类型和 API composable。
2. 实现工作目录切换器。
3. 实现懒加载文件树。
4. 实现只读预览。
5. 添加加载、错误、空状态和国际化文案。

### 阶段三：页面集成

1. 将右栏接入 `TaskNotifications.vue`。
2. 实现宽度调整、折叠和本地状态持久化。
3. 实现窄屏 Drawer。
4. 接入任务切换、请求取消和手动刷新。

### 阶段四：验收与优化

1. 执行 Go、TypeScript、国际化、Lint 和构建检查。
2. 使用普通仓库和大型仓库验证性能。
3. 验证 Windows 与 macOS 路径行为。
4. 修复键盘操作、焦点、溢出和响应式问题。

## 14. 验收标准

满足以下条件即可认为首期完成：

- 用户在 `/tasks` 选择任务后可以展开右侧工作区面板。
- 面板默认显示任务主 `work_dir`，并能切换全部附加 `work_dirs`。
- 展开目录不会触发整个仓库递归扫描。
- 用户可以只读查看支持的文本、Markdown、源码、配置文件和图片。
- 前端不存在任何工作区文件写入入口或请求。
- 路径穿越、未授权 root、符号链接和超限文件均被服务端拒绝。
- 大型仓库打开面板时 UI 不被长时间阻塞。
- 面板在桌面宽屏、窄屏和键盘操作下均可用。
- `go test ./...`、`npm test`、`npm run lint` 和 `npm run build` 通过。
